Segment 2 · 3–10 min

Assignment is a command, not a claim

In math

x = 5 is a claim about the world.

5 = x means exactly the same thing.

In code

x = 5 is an instruction: “store the value 5 in a box I will call x.”

5 = x is a syntax error. You cannot store something into a 5.

patient_id = 42
patient_id = patient_id + 1    # read the RIGHT side first, then store it
print(patient_id)

43

R Same idea, different ink

patient_id <- 42
patient_id <- patient_id + 1
print(patient_id)

43

R uses <- by convention. = also works, but every R codebase you will ever read uses the arrow, so use the arrow.

Naming rules — identical in both languages

  • Letters, digits, underscore. Start with a letter. No spaces.
  • Case-sensitive: Patient and patient are two different variables.
  • bp_systolic is a hundred times more useful than x1. Future-you is a stranger.
  • Anti-pattern: naming every intermediate step data. You will lose track of which step you're on.

Habit to build starting now

When something behaves strangely, check the type before you check anything else. Three seconds, and it is the answer surprisingly often.

Gotcha 1: booleans are secretly numbers

passed_qc = [True, False, True, True, False]

sum(passed_qc)                    # counts the Trues
sum(passed_qc) / len(passed_qc)   # fraction that passed

3   then   0.6

True is 1 and False is 0 when you do arithmetic on them. Same in R: sum(c(TRUE, FALSE, TRUE)) is 2.

This is not a curiosity — it is the idiom

“What fraction of my samples passed QC?” is literally mean(passed_qc). Averaging a column of true/false gives you a proportion.

Gotcha 2: the Excel-to-CSV type disaster

"5" + "3"        # two strings

'53'   — not 8. + on strings means “glue together.”

"5" + 3          # a string and a number

TypeError   — Python refuses to guess what you meant.

Why you will meet this in week 7

One cell in your age column says "unknown", or has a stray comma, or a trailing space. The whole column loads as text. mean(age) then fails — or worse, quietly does something else.

Predict before you run — sixty seconds, with a neighbor

a = 5
b = "5"
c = 5.0
d = True

a == c        ?
a == b        ?
d == 1        ?
b * 3         ?

Commit to an answer out loud before anyone types it.

= assigns.   == asks.

if x = 5 is an error.

This is the single most common beginner typo. It will not be the last time you see this slide.

Gotcha 3: floats are approximate

0.1 + 0.2
0.1 + 0.2 == 0.3

0.30000000000000004   then   False

This is not a Python bug. It is how binary computers store decimals — R does it too, it just prints fewer digits and hides it from you.

Never

if p_value == 0.05:

Instead

if abs(a - b) < 1e-9:
np.isclose(a, b)      # Python
all.equal(a, b)       # R

Segment 5 · 25–30 min

How to read a traceback

Traceback (most recent call last):
  File "analysis.py", line 12, in <module>
    total_age = ages_str + 10
TypeError: can only concatenate str (not "int") to str
  1. Read the bottom line first. That is the actual complaint: Python saw a string on the left of +.
  2. Then the file and line. analysis.py, line 12. Go there.
  3. Then the offending code. Now you know ages_str is a string when you thought it was a number.
  4. Then fix the cause, not the symptom. int(ages_str) + 10 patches it. Better: fix wherever ages_str got assigned.

Pasting the error into ChatGPT

This is a legitimate move — with a catch

ChatGPT reads the same four things you just read, and it is genuinely good at explaining what a TypeError means.

The catch

It does not know what ages_str should have been. It will confidently suggest str(10) — making the numbers into text and producing "4210" — because that also makes the error go away.

Making the error go away is not the same as fixing the bug.

Better prompt: “This errors. I expect ages_str to hold ages as numbers. Where did it become a string?”

Vocabulary and traps

Words

  • Variable — a named box holding a value
  • Assignment — putting a value in the box
  • Type — the kind of value
  • Expression — code that evaluates to a value
  • Traceback — the error report
  • Coercion — converting one type to another

Traps we saw

  • = where you meant ==
  • Assuming CSV numbers loaded as numbers
  • Comparing floats with ==
  • Reading only the top of a traceback
  • Accepting an AI fix that silences rather than solves
