Segment 2 · 3–12 min

Lists and vectors

Python — list

bp = [117, 122, 141, 130, 118]
ids = ["P001", "P002", "P003"]

len(bp)
bp.append(125)

5     then bp has 6 elements

R — vector, built with c()

bp <- c(117, 122, 141, 130, 118)
ids <- c("P001", "P002", "P003")

length(bp)
bp <- c(bp, 125)

5     then bp has 6 elements

c() is short for combine. You will type it ten thousand times this semester.

R vectors are homogeneous — and silent about it

c(1, 2, "three")

"1"  "2"  "three"   — everything became a string. No warning. No error.

This is exactly what happens to your data

One row of your age column says "unknown". R loads the whole column as text. Then mean(age) fails — and you are three steps downstream by the time you notice.

Python lists happily hold mixed types ([117, "high", True] is legal), but you should still keep them homogeneous. A column of one kind of thing is the whole idea.

Contrast with last week: Python refused to mix types and threw a TypeError. R silently converts. Loud failure beats quiet wrongness.

Segment 3 · 12–20 min · draw this on the board

Python counts from 0. R counts from 1.

  value      117      122      141      130      118

  Python       0        1        2        3        4
  Python      -5       -4       -3       -2       -1

  R            1        2        3        4        5

bp[0]     # 117  first
bp[1]     # 122  second
bp[-1]    # 118  LAST

bp[1]     # 117  first
bp[2]     # 122  second
bp[-1]    # 122 141 130 118  ← !!

In Python, -1 means “the last one.”
In R, -1 means “everything except the first.”

Same syntax. Opposite meaning. No error either way.

This is the classic silent bug when you paste code between languages — and AI does it constantly.

Slicing: grabbing a range

Python — stop is EXCLUSIVE

bp[1:4]    # [122, 141, 130]
           # indices 1,2,3 — NOT 4
bp[:3]     # first three
bp[-2:]    # last two

R — stop is INCLUSIVE

bp[2:4]    # 122 141 130
           # indices 2,3 AND 4
bp[1:3]    # first three
bp[c(1,3,5)]  # cherry-pick

Why Python excludes the stop

So that bp[:3] and bp[3:] split the list perfectly with no overlap and no gap, and so len(bp[a:b]) == b - a. It is consistent once you see it — it just isn't intuitive on day one.

Predict — ninety seconds, with a neighbor

bp = [117, 122, 141, 130, 118]     # Python
bp <- c(117, 122, 141, 130, 118)   # R

Python:  bp[2]      bp[1:3]     bp[-2]     bp[:0]
R:       bp[2]      bp[1:3]     bp[-2]     bp[0]

Write your eight answers down before anyone runs anything.

Boolean indexing — the idiom that runs the semester

bp <- c(117, 122, 141, 130, 118)

bp > 130           # FALSE FALSE TRUE FALSE FALSE   ← a mask
bp[bp > 130]       # 141                            ← keep where TRUE
sum(bp > 130)      # 1                              ← count them

Read bp[bp > 130] as: “the elements of bp, where bp is over 130.”

Ring this bell loudly

Every filtering operation you do for the rest of the course is this. dplyr::filter() is this. df[df.age > 65] is this. Learn it here, in five elements, before it arrives with fifty thousand rows.

Segment 4 · 20–27 min

When position is the wrong way to look things up

Sometimes you don't want “the third one.” You want “the one called age.”

Python — dict

patient = {
    "id": "P042",
    "age": 61,
    "systolic": 141,
    "treated": True
}
patient["age"]            # 61
patient["age"] = 62       # update
patient["dx"] = "HTN"     # add

R — named list

patient <- list(
    id = "P042",
    age = 61,
    systolic = 141,
    treated = TRUE
)
patient$age               # 61
patient$age <- 62         # update
patient$dx <- "HTN"       # add

Choosing the container

What you haveReach for
A column of measurements — all one kind of thinglist / vector
One subject's attributes — mixed types, named fieldsdict / named list
A lookup table — gene → chromosome, ID → groupdict / named list
Many subjects, same fields, lined up as a tabledataframe — Session 7

The foreshadow that ties Unit 1 to Unit 2

A dataframe is essentially a list of dicts, stood up as a rectangle — one dict per row, sharing the same keys. Everything you learn today is the machinery underneath week 7.

Where AI gets this wrong

Ask an AI to translate this Python to R

last_reading = bp[-1]

What you may get back

last_reading <- bp[-1]

Runs perfectly. Returns four values instead of one. Never errors. Your “last reading” is now most of the dataset.

What you should have gotten

last_reading <- bp[length(bp)]     # or tail(bp, 1)

You catch this by knowing the rule. Nothing else will catch it.

Vocabulary and traps

Words

  • List / vector — ordered container
  • Element — one item in it
  • Index — its position
  • Slice — a sub-range
  • Boolean mask — a same-length T/F vector used to select
  • Dict / named list — name → value
  • Coercion — R quietly making everything one type

Traps

  • Forgetting Python starts at 0
  • -1 meaning two different things
  • Python's exclusive stop vs R's inclusive stop
  • One string silently coercing an R vector
  • Using position where you meant a name
  • An empty result that isn't an error
