Segment 2 · 3–12 min

Defining and calling

def count_high(bps, threshold=140):
    count = 0
    for bp in bps:
        if bp >= threshold:
            count += 1
    return count


count_high(group_a)
count_high(group_b, threshold=150)

count_high <- function(bps, threshold = 140) {
    count <- 0
    for (bp in bps) {
        if (bp >= threshold) count <- count + 1
    }
    count     # last expression is returned
}

count_high(group_a)
count_high(group_b, threshold = 150)

Two calls. One definition. The duplicated block from slide 2 is gone.

Anatomy

def   count_high  ( bps ,  threshold=140 ) :
 ↑        ↑          ↑          ↑
keyword  name    parameter   parameter with a default

    return count
      ↑
   hands the value back to whoever called
ParameterThe name in the definition — bps, threshold. A placeholder.
ArgumentThe value you pass at the call — group_a, 150. The real thing.
Worth learning properly: error messages say things like “missing 1 required positional argument: 'bps'” and you need to know which noun is which to act on it.

Name your arguments when the meaning isn't obvious

Unreadable

t.test(x, y, TRUE, 0.99)

What is TRUE? Paired? Two-sided? Equal variance? You have to go read the docs to know what this code does.

Self-documenting

t.test(x, y,
       paired = TRUE,
       conf.level = 0.99)

Now the code states its own assumptions. A reviewer — or you in March — can check them.

Why this matters for AI-generated code

AI often emits the terse positional form. Rewriting it with named arguments is a reading exercise that doubles as a correctness check — you cannot name the arguments without finding out what they are.

Segment 3 · 12–18 min

Return, don't print

def print_high_count(bps):        # side effect only
    n = sum(bp >= 140 for bp in bps)
    print(n)

def count_high(bps):              # returns a value
    return sum(bp >= 140 for bp in bps)

x = print_high_count(bps)     # x is None. Useless downstream.
y = count_high(bps)           # y is a number. You can keep working.

Rule of thumb

Compute → return. Printing is for humans looking at output; returning is so the next line of code can use the result.

Segment 4 · 18–24 min

Scope: every function gets its own little world

def demo():
    x = 5
    print(x)

demo()        # prints 5
print(x)      # NameError: name 'x' is not defined

x lived inside demo() and stopped existing when the function returned.

This is a feature, not an obstacle

Scope is what makes functions safe. A function you wrote in September cannot accidentally clobber a variable in your November script, because its x is a different x. Without scope, every variable name in your project would have to be unique.

The global-variable trap

Fragile

threshold = 140          # global

def count_high(bps):
    return sum(bp >= threshold
               for bp in bps)

Reads a value from outside itself. Works — until you copy the function into another script, or someone changes threshold forty lines earlier.

Self-contained

def count_high(bps,
               threshold=140):
    return sum(bp >= threshold
               for bp in bps)

Everything it needs arrives through the door. Same result, same answer, anywhere, forever.

Reading a global is how you get code that “works on my machine” and nowhere else.

Segment 5 · 24–30 min

When should this be a function?

  1. You copied it more than once. Convert it. Non-negotiable.
  2. You want to test one piece of your analysis on its own.
  3. You can name what it does in three words. Then that's its name.
  4. You want to hand it to an AI without pasting your entire analysis.

And the reverse signal

If your function is 200 lines long, it is not one function. It is three or four functions in a trench coat.

Docstrings

def count_high(bps, threshold=140):
    """
    Count how many blood pressure readings meet or exceed a threshold.

    Parameters
    ----------
    bps : list of numeric
        Systolic readings, in mmHg. Missing values are not handled.
    threshold : numeric, default 140
        Cutoff at or above which a reading counts as high.

    Returns
    -------
    int
        Number of readings >= threshold.
    """
    return sum(bp >= threshold for bp in bps)

R The same thing, roxygen-style

#' Count high blood pressure readings
#'
#' @param bps numeric vector of systolic readings (mmHg)
#' @param threshold cutoff, default 140
#' @return integer count of readings at or above threshold
count_high <- function(bps, threshold = 140) {
    sum(bps >= threshold)
}

Note the body: R lets us write the vectorized one-liner from last week. Same function, four lines shorter.

The #' comments are the convention R packages use. Your editor and R's help system both know how to read them.

A good docstring is a specification.

Write the docstring first. Hand it to the AI. Get back a body that matches.

Then verify it. Always verify it.

Why the function is the right unit for AI collaboration

“Analyze my data”

  • The model must guess your goal, your data's shape, your assumptions
  • You get 80 lines you didn't specify
  • Checking it means checking all 80 at once
  • When it's wrong, you can't tell where

“Write this function to this docstring”

  • Inputs, outputs, and edge cases are all stated
  • You get 5 lines with a defined contract
  • You can test it on an input whose answer you know
  • When it's wrong, it's wrong here

The test that costs ten seconds

Call your new function on input where you already know the answer. count_high([100, 200], threshold=140) must be 1. If it isn't, you found the bug before it reached your paper.

Vocabulary and traps

Words

  • Function — named block: inputs → output
  • Parameter — name in the definition
  • Argument — value at the call
  • Default argument — used when caller omits it
  • Return value — what comes back
  • Side effect — anything else it does
  • Scope — where a name is visible
  • Docstring — the contract, in prose

Traps

  • Printing where you should return
  • Copy-pasting a body instead of parameterizing
  • Reaching for a global from inside
  • 200-line functions
  • Accepting an AI function without testing it on a known answer
  • Forgetting return entirely (Python gives you None, silently)
