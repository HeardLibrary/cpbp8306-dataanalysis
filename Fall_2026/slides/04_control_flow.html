Segment 2 · 3–10 min

Conditionals

bp = 145

if bp >= 140:
    print("high")
elif bp >= 120:
    print("elevated")
else:
    print("normal")

bp <- 145

if (bp >= 140) {
    print("high")
} else if (bp >= 120) {
    print("elevated")
} else {
    print("normal")
}
  • Python uses indentation to mark the body. Four spaces, consistently. Mixing tabs and spaces is a real error, not a style complaint.
  • R uses curly braces and does not care about whitespace — but indent anyway, for humans.
  • The condition must produce a boolean — which is exactly what >= and == give you.

elif is not the same as another if

Three independent tests

if bp >= 140:
    category = "high"
if bp >= 120:
    category = "elevated"
if bp < 120:
    category = "normal"

With bp = 145: sets "high", then overwrites it with "elevated". Wrong answer, no error.

One decision

if bp >= 140:
    category = "high"
elif bp >= 120:
    category = "elevated"
else:
    category = "normal"

“Only check this if the previous one didn't fire.” bp = 145 gives "high" and stops.

This is a correctness bug, not a style bug — and it is one an AI will happily write if your prompt describes three separate rules instead of one decision.

Segment 3 · 10–20 min

For loops: do this once per element

bp_list = [117, 122, 141, 130, 118]

for bp in bp_list:
    if bp >= 140:
        print(bp, "is high")

bp_list <- c(117, 122, 141, 130, 118)

for (bp in bp_list) {
    if (bp >= 140) {
        print(paste(bp, "is high"))
    }
}

Read every loop out loud in English

“For each blood pressure in the list: if it is at least 140, print it.”

If you cannot say a loop in one English sentence, you do not understand it yet — and neither will the person reviewing your paper.

The accumulator pattern

count_high = 0                 # start the tally at zero
for bp in bp_list:
    if bp >= 140:
        count_high += 1        # bump it
print(count_high)

1

Three parts, always: initialize before the loop, update inside, use after. Miss the first and you get a NameError; put the third inside the loop and you print five times.

Recognize this shape

This is what an AI writes when you ask it to count, sum, or collect something. It is not wrong. But in a moment we are going to see that the language already knows how to do it.

Segment 4 · the point of the session

Now watch how much of that disappears.

Vectorization: the same job, no loop

count_high <- sum(bp_list >= 140)

That is the entire program. Unpack it right to left:

  • bp_list >= 140 does not compare one number. It applies element-wise to the whole vector, producing FALSE FALSE TRUE FALSE FALSE.
  • sum() on booleans counts the TRUEs — because booleans are numbers (Session 2).

Three sessions converging

Booleans-are-numbers (S2) + boolean masks (S3) + operations that broadcast over a container (today) = the way R was designed to be written.

Python Same idea, two ways

# comprehension — a loop wearing a nicer coat, but idiomatic
count_high = sum(bp >= 140 for bp in bp_list)

# numpy — genuinely vectorized, and what pandas uses underneath
import numpy as np
bp_array = np.array(bp_list)
count_high = (bp_array >= 140).sum()

Plain Python lists are not vectorized — [1,2,3] >= 2 is an error. That is precisely why numpy and pandas exist, and why Session 7 starts there.

R gives you vectorization in the base language. Python makes you import it. Same concept, different packaging.

Why this matters — three reasons, in order

1 — CorrectnessOne line has one place to put a bug. Six lines have six. The loop version has an off-by-one waiting to happen; the vectorized version does not.
2 — Speed10–1000× faster on real data. At a million rows this is the difference between 0.01 seconds and 10 seconds — per operation, in a script you run fifty times.
3 — Readabilitysum(bp > 140) says what it means. A reviewer reads it in one second. A loop takes thirty and a careful eye.

And a fourth, for this course

If you ask an AI “how do I count patients with high BP in R” and it hands you a for loop — that is a code smell. R has sum(bp > 140). Push back and ask for the vectorized version.

Segment 5 · 27–30 min

while, and how to stop one

i = 0
while i < 5:
    print(i)
    i = i + 1     # forget this line and it runs forever

How to stop it

  • Terminal: Ctrl-C
  • VS Code / Jupyter: the stop button
  • RStudio: the red stop sign in the console

When to use it

Rarely. for runs a known number of times; while runs until something becomes false.

If you're writing one, ask: do I actually not know how many iterations I need? Usually you do, and a for is safer.

Vocabulary and traps

Words

  • Conditional / branch — code that runs only if
  • Loop / iteration — same code, once per element
  • Iterable — anything you can loop over
  • Vectorization — operating on a whole container at once
  • Comprehension — Python's [expr for x in xs]
  • Accumulator — a variable built up inside a loop

Traps

  • Writing a loop where a vectorized primitive exists
  • Separate ifs where you meant elif
  • Forgetting to update the while variable
  • Modifying a list while looping over it
  • = instead of == — still
  • Forgetting to initialize the accumulator
